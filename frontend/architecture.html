Technical architecture

Five agents working together as one multi-agent ecommerce system

The orchestrator is the traffic controller. Each agent solves one specialist task, returns evidence, and the final outcome is derived from the full chain.

How AI Orchestration Happens

Simple version: the orchestrator never guesses. It asks the right agent, checks the response, then passes trusted evidence forward.

01

Choose route

The workflow reads the case: FBA uses Prep, MFN uses Pack, returned items use Returns.

02

Call agent

The orchestrator sends a strict request with unit, org, inputs and previous evidence.

03

Validate evidence

Agent output must match schema, tenant, subject, hashes and allowed references.

04

Derive outcome

The final result is calculated from evidence and overrides, not from hidden UI state.

How One Agent Call Works

Every agent follows the same contract, so five separate agents behave like one system.

1. RequestOrchestrator sends org, unit, stage, inputs and previous evidence.
2. Specialist agentAgent checks only its domain: Receiving, Prep, Pack, Returns or Recovery.
3. Evidence recordAgent returns verdict, reason, checks, refs, hashes and next action.
4. ValidationOrchestrator validates schema, tenant, subject and evidence references.
5. Next stageValidated evidence is passed forward to the next agent.

Real-Time Communication Flow

What happens after the user clicks Run workflow. The browser talks only to the orchestrator; the orchestrator talks to the agents.

01 User clicks Run

Frontend sends unit ID, route and returned status to POST /workflows.

02 Orchestrator creates state

It opens or creates one workflow and marks it in progress.

03 Route decision

It decides which stages run: FBA uses Prep, MFN uses Pack, Returns runs only for returned units.

04 Agent call

It sends a strict request to the selected agent with current inputs and previous evidence.

05 Evidence returned

The agent replies with verdict, checks, reason, references, hashes and next-step advice.

06 Validate and continue

The orchestrator validates the response, stores it, then passes it to the next agent.

07 Final outcome

After all required stages, it derives clean, incomplete, review needed or claim recommended.

08 UI updates

The frontend renders the outcome card, timeline and evidence trace for the operator.

Data Flow In Plain English

What moves through the system during a run.

1. InputsPhotos, CSVs and JSON reports are registered to the selected unit.
2. Agent evidenceEach manager returns verdict, reason, checks, refs and hash-backed records.
3. Workflow stateThe orchestrator stores stage state: completed, skipped, blocked or error.
4. Final outcomeCUBE shows claim recommended, clean, incomplete or needs review.
Tenant scoped

Workflows and records belong to one organization context.

Evidence first

Every decision has traceable checks and source references.

Separate roles

Each agent owns one ecommerce domain, making the system easier to debug.

Auditable override

Humans can correct a decision without deleting the original evidence.
